## Checklist for each repository

- [ ] Confirm existing repository, canonical owner, collaborators and personal contribution; preserve original history and author credits.
- [ ] Agree on a separate repository for each distinct individual/collaborative/team project as appropriate. Related exercises may share a course label on the website without combining source. If the instructor permits a course repository, document that decision explicitly.
- [ ] Obtain approval before creating/publishing a repository, pushing code, moving source or changing visibility.
- [ ] Prepare reviewed source and dependency manifests only; exclude virtual environments, node_modules, build output, large models, credentials, private records, survey/patient data and unreviewed media.
- [ ] Add a README with overview/objectives, installation, methodology, saved results, limitations, reproducibility caveats, credits and source/data licenses.
- [ ] Include datasets only when redistribution permission is established; otherwise document access instructions and exact version. Model weights require their own review.
- [ ] Privately review configuration, notebooks, exports and history for secrets and personal data.
- [ ] Review the proposed description/topics above for accuracy, then apply them only with authorization.
- [ ] Verify repository and documentation URLs without authentication before marking them public in the website.
